# VK Музыка в мобильном FLOW

## Подключение с iPhone: номер и код внутри FLOW

Основной путь не открывает QR-ссылки и другие вкладки. Пользователь вводит номер
в FLOW, сервер передаёт его в настоящую форму VK ID. Затем коннектор определяет
текущий шаг: SMS, код приложения, цифры звонка или дополнительная проверка.
FLOW показывает соответствующее поле. Длину кода определяет форма VK.
Поле номера VK использует маску и сбрасывает обычную вставку целой строки.
Коннектор вводит номер посимвольно, сверяет все цифры с введёнными пользователем
и только затем нажимает «Продолжить». При ошибке доставки FLOW сохраняет номер
в открытом поле, не отправляя его повторно автоматически.
Отправленные коды и номера не журналируются и не сохраняются FLOW отдельно.
Авторизованное состояние браузера VK хранится зашифрованным.

Закрытие диалога, возврат из другого приложения и перезагрузка страницы
продолжают ту же попытку. Новый вход создаётся только при отсутствии сессии
или явном выборе «Сбросить и начать заново». Номер и код передаются отдельными
POST-запросами с проверенной Telegram-идентичностью и подписанным RPC.

После перехода VK ID в аккаунт коннектор открывает музыкальную страницу.
Для статуса «Подключён» требуется успешный `audio.get` с массивом `items`;
наличия cookies или `vkApi` недостаточно. Пустая библиотека допустима. При отказе
API интерфейс сообщает, что вход выполнен, но музыка пока недоступна.
Пароль и дополнительные проверки проходят в резервной форме VK.

**Проверено на настоящем VK:** открытие формы телефона. **Проверено тестами:**
передача номера и кода, продолжение после перезагрузки без повторной отправки,
повторный ввод кода, отказ музыкального API и изоляция пользователей.
**Не подтверждено:** полный вход реального пользователя, переход в авторизованную
музыкальную сессию и загрузка настоящего трека на iPhone. Старый вход через
приложение оставлен в backend для совместимости; основной интерфейс его не запускает.

Сервер всё ещё нужен: он получает сессию VK. Пользователь видит это объяснение
перед вводом номера. Постоянный сервер пока не развёрнут.

## Как работает получение музыки

Для этого способа **не нужно регистрировать приложение VK Audio API и не нужен
компьютер пользователя**. Отдельный Node.js-коннектор запускает Chromium на
сервере FLOW. Для дополнительной проверки Mini App может показать его окно
на телефоне и передавать пользовательские клики, жесты и ввод. Вход происходит
на настоящих страницах VK. После входа
коннектор использует `window.vkApi.api` в пользовательской сессии — тот же
механизм, что FLOW Desktop.

Это удалённый браузер: ввод и сессия проходят через сервер FLOW, поэтому его
владелец должен быть доверенным. В интерфейсе это указано перед вводом.
Коннектор не является официальной интеграцией VK; изменения сайта, проверки
входа и ограничения VK могут влиять на работу. Проверки проходит пользователь,
коннектор их не обходит.

Поддержаны:

- автоматический сбор всего списка личной музыки и выбранного плейлиста;
  прогресс, остановка и продолжение; отображение списка порциями по 100 строк;
- поиск через `audio.search` и каталог VK, как в десктопе;
- загрузка по VK identity с обновлением ссылки перед воспроизведением;
- поиск другой доступной загрузки той же песни, если выбранная недоступна;
- обычные аудиофайлы и конечные HLS-потоки: MPEG-TS, AES-128, fMP4 `EXT-X-MAP`
  и byte ranges; преобразование в MP3 через ffmpeg на сервере;
- один и тот же коннектор для PHP-хостинга и Cloudflare Worker;
- изолированные браузерные контексты пользователей, зашифрованное сохранение
  сессии и её удаление при отключении VK.

До 20 МБ и 12 минут на трек. DRM/SAMPLE-AES и прямые эфиры не поддерживаются.
Файлы с телефона остаются в IndexedDB на устройстве. Автомикс и мэшап выполняются
в существующем Web Audio движке Mini App.

## Что нужно для запуска

Нужен выбранный сервер или контейнерная платформа с Chromium и ffmpeg.
Обычного PHP-хостинга или одного Cloudflare Worker для браузерного способа
недостаточно: они обращаются к отдельному коннектору.

В репозитории есть `vk-connector/Dockerfile` и `vk-connector/compose.yaml`.
Compose по умолчанию ограничен 2 ГБ памяти, двумя открытыми окнами и публикует
порт только на loopback. Неактивные окна закрываются через 15 минут, сессия
сохраняется в зашифрованном виде до 30 дней. При повторном открытии VK может
попросить новый вход.

## Проверка на телефоне до выбора хостинга

`node vk-connector/phone-preview.mjs` запускает отдельную временную страницу
проверки на loopback-адресе и выводит личную ссылку с ключом во фрагменте URL.
Для доступа с iPhone можно направить временный HTTPS-туннель только на выведенный
порт. Не направляйте туннель на каталог репозитория или внутренний RPC-порт.

Страница использует настоящие модули входа и библиотеки FLOW, позволяет загрузить
трек и проверить звук стандартным плеером iPhone. Это отдельная ручная проверка,
не обход Telegram-аутентификации в основном приложении. API теста защищён случайным
256-битным ключом. Библиотека временная, сессия отдельная, время работы ограничено
часом. Кнопка «Отключить VK и удалить сессию» удаляет сессию сразу; при завершении
процесса временное хранилище тоже удаляется. Ссылку нельзя пересылать другим людям.

Этот тест использует Mac разработчика. Постоянный мобильный сервис должен
использовать сервер, чтобы компьютер пользователя не требовался.

Кнопка «Подключить VK» открывает ввод номера, затем кода внутри FLOW.
Код очищается при отправке; номер — при переходе к следующему шагу. Закрытие
окна очищает оба поля; сервер сохраняет текущий шаг входа.
Временный публичный адрес тоже должен оставаться доступным: туннели, меняющие
домен во время теста, для проверки возврата с телефона не подходят.

## Развёртывание коннектора

1. На выбранном сервере установите Docker с Compose и скопируйте репозиторий.
2. Создайте `vk-connector/.env` на основе `.env.example`.
   Для `FLOW_CONNECTOR_SECRET` сгенерируйте случайный секрет:

   ```sh
   openssl rand -hex 32
   ```

   Не публикуйте его и не вставляйте в чат. `.env` исключён из Git.
3. Запустите из корня репозитория:

   ```sh
   docker compose -f vk-connector/compose.yaml up -d --build
   curl http://127.0.0.1:8788/health
   ```

4. Для обращения с другого хоста настройте HTTPS reverse proxy к
   `127.0.0.1:8788`. Коннектор принимает только подписанные запросы бэкенда.
   Не включайте запись HTTP request bodies: они содержат ввод пользователя.
   Таймаут прокси для аудио должен быть не меньше 300 секунд.
5. Держите volume `vk-sessions` и секрет в сохранности. Смена секрета делает
   сохранённые сессии нечитаемыми — пользователям потребуется повторный вход.

Контейнер работает от `pwuser`, с read-only filesystem, ограниченной памятью
и без Linux capabilities. Отдельный сервис не получает Telegram bot token.
Запросы подписаны HMAC с временем и одноразовым nonce; произвольное выполнение
JavaScript и произвольная навигация через его API не доступны. Сессия выбирается
по Telegram ID, подтверждённому бэкендом. ffmpeg читает только подготовленные
локальные данные и не обращается в сеть.

## Подключение PHP

Добавьте в существующий `flow/api/config.local.php`:

```php
'vk_connector_url' => 'https://vk-connector.example.com',
'vk_connector_secret' => 'ТВОЙ_FLOW_CONNECTOR_SECRET',
```

Если PHP и коннектор работают на одном сервере, допускается приватный HTTP
адрес `http://127.0.0.1:8788`. Если PHP тоже в контейнере, используйте адрес
сервиса в приватной Docker-сети. Секрет должен совпадать с `.env` коннектора.
Поля `vk_client_id`, `vk_client_secret`, `vk_redirect_uri` не нужны.

Загрузите обновлённую папку `flow/`, включая `.htaccess` и новые JS/PHP-файлы.
Данные `flow/data/` должны оставаться недоступными по HTTP. На nginx повторите
запрет доступа к data и PHP-helper-файлам, разрешая только app/bot/setup и
необязательный vk-callback. Нужны PHP 8+, curl, openssl и mbstring. ffmpeg
на PHP-хостинге не требуется — он находится в коннекторе.

## Подключение Cloudflare Worker

Из папки `cloudflare` задайте:

```sh
npx wrangler secret put VK_CONNECTOR_URL
npx wrangler secret put VK_CONNECTOR_SECRET
```

URL должен быть HTTPS. Секрет совпадает с `FLOW_CONNECTOR_SECRET`. Затем
соберите и разверните Worker обычным способом. HLS в этом варианте обрабатывается
коннектором, поэтому отсутствие ffmpeg внутри Worker не мешает.

KV хранит только мобильную библиотеку; браузерные сессии находятся в коннекторе.
Изменения библиотеки в KV могут появляться на другом устройстве с задержкой.
Для строго последовательных изменений библиотеки используйте PHP-хранилище
с блокировками; текущий Worker не использует Durable Objects.

## Использование с телефона

1. Откройте FLOW через Telegram-бота → «Из VK» → «Подключить VK».
2. Введите номер с кодом страны и нажмите «Продолжить». Введите код,
   который запросил VK, в появившемся поле FLOW и нажмите «Подтвердить код».
   Возврат и перезагрузка сохраняют попытку. Для смены номера есть явный сброс.
3. После подтверждённого подключения выберите треки в «Моей музыке», плейлисте
   или поиске, добавьте их и запускайте сет.
4. Если VK требует дополнительную проверку, нажмите «Открыть проверку VK».
   В появившемся удалённом окне коснитесь кнопки или поля VK. Для ввода используйте
   поле под изображением и кнопку «Ввести». Есть Enter, удаление, переход к
   следующему полю и прокрутка. Для жестов внутри VK включите «Перетаскивать в VK»; в обычном режиме можно прокручивать окно FLOW.
5. Пройдите проверки VK самостоятельно. FLOW не подбирает код и не решает CAPTCHA.
   Нажмите «Я вошёл — открыть музыку». Если VK уже подтвердил вход, Mini App
   вернётся к библиотеке автоматически.
6. «Отключить» закрывает серверный браузер, удаляет его сохранённую сессию,
   VK-треки мобильной библиотеки и кэш аудио на текущем телефоне.

Для проверки VK во время работы можно открыть кнопку «Окно VK».
Удалённое окно использует изображение, поэтому доступность этого этапа для
экранных дикторов ограничена; сами списки музыки — обычные доступные элементы UI.

## Необязательный OAuth-вариант

Старый путь оставлен для владельцев приложения VK с реально разрешённым
Audio API и OAuth authorization code flow. Он используется только когда
коннектор не настроен. Обычный VK ID сам по себе такого доступа не гарантирует.

PHP: `vk_client_id`, `vk_client_secret`, точный HTTPS `vk_redirect_uri`,
а для HLS — `ffmpeg_path`. Callback: `/api/vk-callback.php`.
Cloudflare: `VK_CLIENT_ID`, `VK_CLIENT_SECRET`, `VK_REDIRECT_URI`.
Без коннектора Worker поддерживает только прямые аудиофайлы; PHP-конвертер
OAuth-варианта не поддерживает fMP4/byte ranges.

## Что проверено и что ещё не проверено

`npm test` проверяет подписанные RPC-запросы, повторный nonce, разделение
пользователей, реальные HTTP-вызовы PHP и Worker → коннектор, импорт и чтение
аудио, каталог и подбор доступного трека, шифрование сессий, OAuth, HLS и
реальную конвертацию синтетического аудио через установленный ffmpeg.

`npm run test:browser` (Chromium) и `npm run test:webkit` (WebKit) проверяют мобильный UI на 320/390/430/768 px, импорт,
частичные ошибки, IndexedDB, настоящее Web Audio воспроизведение тестового WAV,
удалённые поля ввода и возврат к музыке. Отдельно запускается настоящий Chromium
с тестовой страницей VK: проверяются кадр, ввод, API страницы, изоляция,
восстановление зашифрованной сессии и выход. Новый вход проверяется на тестовых
страницах: номер и SMS-код вводятся без смены вкладки, перезагрузка сохраняет
текущий шаг без новой отправки, неверный код можно ввести повторно. Redirect
аккаунта проверяется отдельно от успешного запроса к музыке, данные разных
пользователей не смешиваются. Старый вход через приложение также покрыт тестом.

Прямой вход с музыкальной страницы настоящего VK дошёл до проверки «не робот».
Она не проходилась автоматически. Новый путь через публичную страницу VK ID
успешно открывает форму телефона. **На реальном аккаунте подтверждены вход, список из 1156 треков, восстановление сессии в новом процессе и нативное WebKit-воспроизведение реального MP3 с HTTP Range.** Для завершения нужны
выбранный и развёрнутый сервер, пользовательский вход и проверка на iOS/Android
в Telegram. Браузерные тесты используют имитацию аккаунта и ответов VK и не
заменяют эту проверку.

Закрытие Mini App не гарантирует продолжение Web Audio воспроизведения в фоне.
Мэшап использует существующую нейросеть на телефоне и требует достаточно памяти.

Docker-проверка после сборки образа `flow-vk-connector:local`: `npm run test:container`.
Она запускает временный контейнер без root, с read-only filesystem и проверяет
RPC, Chromium, запись зашифрованной сессии и конвертацию в MP3.
Локальная сборка остановилась при распаковке базового образа: на диске осталось
около 124 МБ, Docker вернул `read-only file system`. Поэтому контейнерная проверка
пока не выполнена; нужны свободное место и исправно работающий Docker.


## REG.RU + бесплатный сервер коннектора

`render.yaml` создаёт только Web Service на тарифе Free. Для применения нужен
аккаунт Render и подключённый репозиторий. Никакой платный диск не создаётся.

1. Разместить `flow/` в отдельном каталоге сайта, не заменяя существующий сайт.
   Сохранить `.htaccess`, включая запрет доступа к `data/` и файлам конфигурации.
2. В Render указать `FLOW_STATE_URL=https://<сайт>/flow/api/vk-state.php`.
3. Одинаковый `FLOW_CONNECTOR_SECRET` указать в Render и в `vk_connector_secret`
   файла `api/config.local.php`; в `vk_connector_url` — HTTPS-адрес Render.
   Токен Telegram-бота и `allowed_users` также задаются только в локальном конфиге.
4. Проверить `/data/` и `/api/config.local.php` снаружи: доступ должен быть запрещён.
   Сам endpoint `vk-state.php` без HMAC должен отвечать 401.
5. Проверить реальный вход и воспроизведение после размещения: смена IP сервера
   может вызвать дополнительную проверку VK. Код/капчу проходит пользователь.

Хранилище принимает только подписанные запросы коннектора, отклоняет повторы
nonce и записывает AES-GCM ciphertext. Ключ расшифровки — секрет коннектора.
При недоступности хранилища операция завершается ошибкой, а не новым входом.
Кнопка отключения удаляет сохранённую сессию. Активная незавершённая форма входа
не переживает перезапуск браузера; подтверждённая сессия сохраняется отдельно.

Ограничения бесплатного сервиса: https://render.com/docs/free . Это вариант для
личного использования с холодным стартом и лимитом трафика, не SLA продакшена.

## Manual DJ mode

Two independently loaded Web Audio decks, equal-power crossfader, low/mid/high EQ, cue and seek, ±16% tempo, four-beat loop and ±20 ms nudges. Sync matches BPM only; phase alignment is manual and pitch follows tempo. Selecting a deck downloads/decodes that selected track in memory; ordinary listening uses native audio requests. Switching to another playback mode releases the manual deck buffers. This is not persistent offline storage of the VK collection.

WebKit and Chromium UI tests cover simultaneous playback, cue, loops, mode navigation and narrow viewports. Audio-clock tests cover tempo continuity and loop release. Waveform editing, pitch-preserving time stretch and separate headphone monitoring are not implemented.
